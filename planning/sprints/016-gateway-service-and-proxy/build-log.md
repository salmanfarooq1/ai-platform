## Source map
- **Verified identity:** `core/identity/jwt.py` (`JwtVerifier._verify`, `principal_from_claims`, `verify`) validates configured issuer/audience/expiry/sub and projects claims to `Principal`. `Principal` in `core/identity/models.py` keeps id, tenant, kind, scopes and optional API-key `credential_id`; it has no agent binding and JWT `act`/issuer facts do not survive projection. `api/middleware/auth.py` distinguishes API key (`authenticate_api_key`), run token (`authenticate_run_token`, path-bound), JWT (then `confirm_jwt_principal`) and browser session. Invalid credentials have no trusted principal for a recorded decision; preserve generic 401. Current console session and API-key paths are not issuer-verified JWTs.
- **Gateway:** `api/gateway_deps.py` builds one context with `build_context`; `gateway/context.py` fixes tenant policy and boundary; `gateway/enforce.py::enforce` decides and records, converting an unrecorded allow into `decision_unrecorded`. Keep this as decision authority. `api/agent/router.py::agent_query` performs entry `agent.run`, KB and model checks before starting `adapters.runtime`.
- **MCP today:** `api/main.py` mounts `handle_messages` and `handle_sse`. `api/mcp/transport.py` defines `SseApp`/`MessagesApp`, checks a verified Principal on connect, calls `enforce`, and sets/resets `current_principal` for message handling. `api/mcp/context.py::gate` builds a fresh gateway context for each tool/resource action. Tool definitions and gateway checks are in `api/mcp/tools.py`; bounded expected-error masking is `api/mcp/server.py::_expected_errors` (011 correction). `mcp`, `sse_transport`, and `mcp._dependency_overrides['app_context']` are module-global. `init_mcp_context` overwrites that shared app context at lifespan start; a new stateless implementation must avoid cross-app or cross-request caller state.
- **Runtime/model seams:** `ports/runtime.py::AgentRuntime` has start/status/wait/stop/cleanup; concrete choices are composed in `adapters/registry.py::build_adapters` and `build_local_runtime`. Model ports are `ports/llm.py` (`LLMPort`, `ChatModelPort`); implementations are `adapters/litellm_llm.py`, `litellm_chat.py`, and `litellm_embeddings.py`. Current route work can reuse these only behind the 013 resolved-target/per-attempt authorization seam; the accepted 013 contracts are not in this 011 source snapshot.
- **UI reuse:** `ui/src/app/router.tsx` adds lazy app pages; `app/nav.ts` is the static sidebar list and `app/command-palette.tsx` builds from `palette-items.ts`. No MCP registry or Agents registration/stop route exists. Reuse `features/keys/keys-page.tsx` for scoped identity/status tables; `features/policies/policies-page.tsx` for revision selection; `features/library/library-page.tsx` and `upload-dialog.tsx` for mutation/query invalidation patterns; `components/governance/states.tsx` for loading/error/empty states; `components/ui/button.tsx` and existing Dialog-based `features/trust/receipt-verifier.tsx` for accessible actions/dialogs. API additions belong in `api/endpoints.ts`, types are generated through `api/types.ts`/`schema.d.ts`; writes use the shared CSRF-aware `api/client.ts`. `app/session.tsx::can` checks scopes, but nav and palette are static and independently composed, so new admin links need a shared filtered navigation source rather than a page-only permission check.

## Open contract questions for Architect
- Specify how a verified issuer credential binds to a registered `agent_id`; do not infer agent identity from caller-controlled AuthZEN subject, header, body, JWT `sub` without a defined trusted binding, or `Principal.kind` alone. Keep issuer-owned token issuance and verification keys/configuration outside platform ownership.
- Define the eligible credential classes and required retained facts for proxy routes: issuer/audience/expiry/sub and any `act`/client identity must come from verified claims; API keys, browser sessions and run tokens cannot silently impersonate an issuer JWT or external agent registration.
- Define registry owner/admin authority, tenant scoping, stop/reapproval revision semantics and whether a stop takes effect on an already authorized/in-flight request.
- For external authorization, settle exact action/body/model-target/revision binding, replay/expiry/cache behavior before treating an allow as executable. Otherwise label the optional data-plane spike unsupported and use the ASGI proxy.
- Existing process-global MCP server/context is a concrete isolation risk for multi-app lifespans and concurrent tests: determine whether Sprint 016 constructs transport/server state per app or introduces an explicit safe ownership boundary. Per-request ContextVar does not make the global app-context dictionary app-local.
- The unchanged-client/base-URL story still needs an explicit supported way for an OpenAI client to supply agent/run/purpose/trace context and gateway credentials; current `api/client.ts` does not apply because it only serves the browser session API, and a silent privileged default would conflict with missing-context denial.
