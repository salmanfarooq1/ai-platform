# Sprint 016: Architect readiness

Preparation only. Finalize the full contract against accepted 012–015 code; no product implementation or acceptance is claimed.

## Verified source boundaries
- `core/identity/jwt.py` verifies issuer, audience, expiry and subject, then projects only `Principal`. `act`, agent identity and verified credential kind are not retained. `api/middleware/auth.py` also accepts API keys and web sessions on existing routes. The new request contract must identify which routes require a JWT and retain trusted verification facts without reparsing unverified claims or breaking existing browser/key/run-token contracts.
- Authentication and database confirmation precede enforcement. An invalid credential has no trusted tenant under which to write a decision. Preserve generic 401 for invalid credentials; distinguish authenticated missing-context denials that can be recorded under the verified principal. Never take tenant or authority from an AuthZEN subject, header or body.
- Current MCP uses `SseApp` and `MessagesApp` in `api/mcp/transport.py`, with per-request `current_principal` set/reset. Every new stateless request needs equivalent verified context isolation; process-global app resources must not become caller state. Keep the bounded expected-error masking implemented in 011. The dedicated Builder confirmed that the MCP server, SSE transport and injected app-context dictionary are module-global and overwritten by another application lifespan. The 016 contract must construct protocol/transport/provider state per application and test two concurrently active application factories with different adapters; resetting a principal ContextVar alone is insufficient.
- `Principal` has an id, tenant, kind, scopes and optional API-key credential id. It does not bind a caller-supplied registry agent id. Specify a trusted principal/credential-to-agent binding and tenant-scoped stop/reapproval checks before implementing the registry.
- The 012 mandatory evidence sink and route module attribution, and the 013 resolved-model/per-attempt authorization and secret resolver, are prerequisites. Do not rebuild their logic inside a proxy.

## Contract issues the Architect must resolve
- Distinguish the M1 protocol/proxy front from the M3 local MCP tool server. The 012 attribution deliberately disables existing agent/MCP routes when M3 is off; 016 must specify how Gateway edition governs external tools without loading local agent execution or bypassing those disabled local-tool routes. Give each registered route its actual trusted module rather than weakening the earlier guard.
- A standalone `authorize()` allow is not automatically an execution capability. Bind any external-authorizer result to the verified identity, tenant, agent, exact canonical action/body, resolved target identity and current registry/policy revisions; define replay, expiry, cache and execution semantics. Otherwise select the own ASGI proxy as the supported data plane and report the optional spike honestly.
- Header prechecks can reject obvious policy violations before reading a body. They cannot grant execution until bounded body parsing establishes that method/name/parameters agree. Test duplicate headers, header/body mismatch, oversized/malformed input, version negotiation and zero downstream calls on denial.
- An unchanged OpenAI client still needs a gateway credential and the required agent/run/purpose/trace context. Resolve the conflict between “only the base URL changes” and “missing context denies” explicitly; document supported standard-client configuration rather than adding an undocumented privileged default. Streaming must authorize the actual resolved attempt before the first byte, propagate cancellation and preserve cost/accounting behavior.
- The platform verifies issuer tokens; it is not an OAuth authorization server. Describe downstream server credentials using the 013 secret boundary or an explicit issuer exchange contract. Do not invent token-issuing authority or pass an inbound bearer to another server.
- Signed manifests need a pretrusted signer and a defined canonical signature payload. A key supplied by an untrusted manifest cannot approve itself. Define approval revision and tool-definition hashes, with admin approval/reapproval in the same sprint's MCP registry UI.
- URL validation must apply to discovery, metadata, manifests, redirects and downstream calls, not only the initial registry URL. Keep credential values out of URLs, state and evidence. Production host/origin allowlists must retain DNS-rebinding protection.
- The Agents UI needs registration, actual stopped status and the authorized Stop flow now. Do not defer these to the richer 028 registry. Record loading/error/denied states and end-to-end stop/reapproval journeys in the full pack.

## Primary protocol checks
The [2026-07-28 transport specification](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports) makes request-body metadata authoritative and describes HTTP headers as mirrors whose mismatches are rejected. The [Python SDK deployment guide](https://py.sdk.modelcontextprotocol.io/run/deploy/) distinguishes the modern sessionless path from the legacy `stateless_http` setting and documents host/origin protection. Recheck behavior in the exact locked SDK before implementation.

The [MCP authorization specification](https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization) separates resource server, client and authorization-server responsibilities, and requires protected-resource metadata for supported HTTP authorization. Resource-server work does not imply that this platform implements the issuer or client registration service.
