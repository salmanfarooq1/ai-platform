# Sprint 005: Frontend foundation and showcase. Requirements

A vertical slice. The API contract comes first (`blueprint.md`), then the backend brief, then the frontend brief, and one e2e test that runs across both.

## Why
The UI is a plain JavaScript SPA that sends a preview key injected by nginx. It can't show the platform's main feature, which is governance: who did what, under which policy, and whether it was allowed. From now on the frontend is first-class.

## Requirements
1. **Web edge (ADR-0007).** A thin module inside the API, not a separate service.
   - Sign in with an API key. The server checks the key and creates a session in Redis that holds the principal, tenant and scopes, never the key itself.
   - The browser gets an HttpOnly, SameSite=Strict cookie (`Secure` outside `local` mode) and a CSRF token.
   - Unsafe methods (POST, PUT, PATCH, DELETE) with a cookie session need a matching `X-CSRF-Token` header.
   - In `public-preview` mode, a visitor can start an automatic read-only session for the configured preview principal. Read-only means `kb:write` and `admin` are always removed.
   - Bearer keys and JWTs keep working unchanged for API and MCP clients.
2. **Console read endpoints.** Tenant-scoped, read-only, under RLS, and gated by `enforce()` with a new action `audit.read` granted by a new scope `audit:read` (and `admin`). The endpoints:
   - a decisions list with filters and a cursor
   - a decision detail with its request trace
   - policies: the list and one version
   - principals and keys, with no secrets
   - a usage summary
3. **OpenAPI.** Every new route is typed with Pydantic response models and is in `docs/openapi.json`.
4. **Frontend stack.**
   - React + Vite in TypeScript (strict), Tailwind and shadcn/ui themed from `ui/src/styles/tokens.css`.
   - A client generated by `openapi-typescript` from `docs/openapi.json`, with TanStack Query.
   - Vitest + Testing Library, ESLint, `tsc --noEmit` and Playwright, all in CI.
5. **Information architecture.**
   - Workspace: Ask, Library, History.
   - Governance: Decisions explorer, Policies, Keys and principals, Budgets and usage, Agent runs.
   - Trust (a placeholder until Sprint 008) and System.
   - A public landing page.
6. **Design.**
   - Follow `.claude/skills/governed-design/SKILL.md`.
   - Refresh `docs/UI_GUIDELINES.md` through it: verdict states, the trace pattern, a dense console versus a calm workspace, both themes, WCAG AA, and empty, loading and error states.
7. **Landing page.**
   - What the platform does, and a GSAP scroll story of one governed request.
   - A lazy WebGL hero (three.js) with a poster fallback and a call to action into the workspace.
   - Lighthouse performance ≥ 85 on desktop, and it respects reduced motion.
8. **Parity, then removal.** Remove the old JavaScript UI and the nginx key injection only once the new UI covers Ask, Library and System.

## Out of scope
- Editing policies or keys from the UI (the admin CLI stays the writer).
- Hosting and deployment (parked).
- Live ingestion progress (Sprint 007).
- Trust content (Sprint 008).
- Sandbox events (Sprint 009).
