## Log
- **Facts first.** GitHub's API and `github.com/.../releases` pages were blocked, but `raw.githubusercontent.com`, PyPI and the release asset downloads worked. Confirmed: NVIDIA/OpenShell exists, `LICENSE` at tag `v0.1.2` is Apache-2.0, PyPI has `openshell` 0.1.0 to 0.1.2 (wheel hash matches the release's checksum file), the docs at the tag (support matrix, policy schema, logging) are readable. `docs.nvidia.com` is blocked. Read the 0.1.2 wheel: the SDK is a synchronous gRPC client (`SandboxClient`, `exec_stream`, `create_from_template`, `WatchSandbox`, a `SandboxPolicy` message). Sources, versions and hashes are in `docs/runbooks/openshell.md`.
- **Plan change.** The first plan was a fake plus a clearly marked stub driver. Once the SDK and the gateway package could be read and downloaded, wrote the real driver against the pinned SDK (`scripts/verify/openshell_sdk_surface.py` checks every call and message it uses against the wheel) and then tried it live.
- **Built.** Gateway: `tool_arguments` in the policy and boundary, the argument check in the policy stage, reasons `tool_argument_not_allowed` and `run_token_scope`. Migration `0010`. Run tokens, the middleware branch, `/v1/sandbox/runs/...`. `ports/sandbox.py`, the runtime, the SDK driver, event cleaning and classification, `sandbox_agent/entry.py`. Runs API `sandbox_events` and `timeline`. UI `RunSteps`. Tests, `tests/fake_sandbox.py`, the Playwright seed in `scripts/e2e/serve.py`.
- **Broke and fixed (fake tier).** The fake driver's events came from a thread and raced the exit message (events could arrive after the exit): every message now goes through one thread-safe `put`. A foreign key on `run_tokens.principal_id` let one tenant point a token at another tenant's principal, because a foreign key check ignores row-level security: the key is now `(principal_id, tenant_id)` with a unique pair on `principals`. The existing `ask-run` Vitest mocks typed `agentRun` as the list shape: added `agentRunDetail` instead of changing the type.
- **Live OpenShell, what it took (all recorded in the runbook).** The container has Landlock ABI 7, Docker 29 and the release downloads, so OpenShell could run here. (1) The gateway from the checksum-checked Debian package starts with the Docker driver. (2) `ghcr.io` blobs are forbidden for the Docker daemon, so the supervisor and runtime images were built locally from the checksum-checked release archives (first attempt had only one binary; the supervisor container needs `/openshell-supervisor` and the extractor needs `/openshell-sandbox`, in the same image; the gateway keeps image ids until restarted). (3) `--disable-tls` cannot create Docker sandboxes: mTLS needed. (4) A root image is refused (uid 0). (5) The work directory cannot be created inside, it must be in the image. (6) Names over 19 characters are refused: found with the first real create. (7) A network rule names the interpreter's real path (`/usr/bin/python3.10`), not the symlink: found because the gateway call was denied. (8) OpenShell's baseline read paths include `/etc`, so the first A4 probe (`/etc/hostname`) was readable: moved to `/var/lib/dpkg/status`. (9) OpenShell logs no event for a refused file read: the probe's report becomes the event, marked as such. (10) Exit 137 for the memory limit, no event: recorded as `limit_hit` with its source.
- **Result.** `scripts/verify/openshell.sh` passes A2, A3, A4, A5 and L1 to L3 against the live gateway. Output in `evidence/openshell-live.txt`.
