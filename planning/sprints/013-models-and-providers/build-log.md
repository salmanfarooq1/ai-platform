# Sprint 013 preparation source map

Read-only preparation against this checkout (Sprint 011 accepted source); Sprint 012 implementation snapshot was not present in this worktree. No code, tests, dependencies, models, containers, cloud services, branches or git metadata were changed. Sprint 013 implementation and acceptance remain pending the accepted 012 snapshot and finalized contract.

## Physical inference paths observed

- **Plain chat completion / synthesis.** `api/routers/search.py` gates the configured `LLM_CONFIG["model"]` once before cache/retrieval and calls `api.services.llm.generate_with_routing` on a cache miss. `api/services/llm.py::generate_with_citations` makes up to three `LLMPort.complete` attempts for rate-limit-looking errors; each uses the same configured alias. It currently logs a query snippet on truncated output. Adapter is `adapters/litellm_llm.py::LitellmLLM.complete` -> `litellm.acompletion`; there is no explicit retry override here. `api/agent/graph.py::synthesize_node` separately calls the same service after one `_model_allowed` check. A service retry therefore follows one allow today.
- **Agent reasoning/chat and verification.** `api/agent/graph.py::make_agent_node`/node code creates a reasoning `ChatModel` and verifier `ChatModel`, with calls at `ainvoke` sites (around lines 263 and 293). `_model_allowed` checks the single configured `LLM_CONFIG["model"]`; inspect exact call context in the full 012 snapshot before implementation. `verify_router` can loop back to agent (`max_verify_retries` settings/config), causing more reasoning attempts; verifier is a separate physical call. `adapters/litellm_chat.py::LitellmChat.chat_model` constructs `ChatLiteLLM` with model/max_tokens/temperature and no explicit retry control; `ainvoke` wraps LangChain/LiteLLM behavior. Readiness notes observed `ChatLiteLLM(max_retries=1)` semantics as one total wrapper attempt; confirm against accepted dependency lock and disable SDK-level hidden retries carefully.
- **Embedding, search and query cache.** REST `api/routers/search.py`, agent `api/agent/tools.py::make_retrieve_tool`, and MCP `api/mcp/tools.py::search_documents` each do a single gateway allow on configured embedding alias before `embed_query`. These are preflight alias permissions, not per-physical-target decisions. `adapters/litellm_embeddings.py::LitellmEmbeddings.embed` tries primary then every `EMBED_FALLBACK_MODELS` item sequentially in `_embed_with` -> `litellm.aembedding`, returning the fallback's actual alias and dimension if successful. No per-attempt decision; fallback list is configured in `core/settings.py::embed_fallbacks` / `embed_fallback_models`. `core/services` query embedding wrapper is `api/services/embedding.py::embed_query`.
- **Ingestion worker batches.** `POST /v1/ingest` (`api/routers/ingest.py`) currently performs one model.invoke preflight for embedding at submit time, then queues durable work. `workers/handlers/ingest.py::make_ingest_handler` executes later; `core/pipeline/db_ingest.py::ingestion_pipeline` calls `embed_chunks` once per chunk batch (default batch size 50), so every batch can trigger primary and embedding fallback physical calls without execution-time model authorization. Worker retries can repeat the handler/job.
- **Optional local cross-encoder reranker.** `api/services/retriever.py::get_cross_encoder` lazily constructs `sentence_transformers.CrossEncoder("cross-encoder/ms-marco-MiniLM-L-6-v2")`; `rerank` invokes `model.predict` via `run_cpu_bound`. Enabled when `FEATURES["reranker_enabled"]` (false only in public-preview in `config.py`) and requested/effective rerank is true; search request `rerank` and agent/MCP configs also control invocation. This is physical local inference outside LiteLLM/Ollama and currently has no model.invoke decision or identity/provenance field.
- **Health probe.** `api/routers/health.py::_check_embedding` -> `_probe_once` calls `embeddings.embed(["health check"])`, caches status (60s success/10s failure), retries once after 1s on error. Thus public `/health` and `/v1/health` can cause embedding provider/fallback inference; they are unauthenticated per repo rules. Sprint 013 readiness requires metadata-only health with zero inference.

## Authorization, identity and adapter seams

- Current gateway `require()`/`enforce()` records the input hash and action alias; callers commonly preflight before cache lookup and before I/O. It does not bind a physical route, resolved provider identity or each fallback/retry. `gateway_decisions` receipts currently expose summary fields and input SHA only; no model extension exists in `api/models/console.py` / `api/models/trust.py`.
- Existing model ports are `ports/llm.py` (`LLMPort`, `ChatModelPort`, `Completion`) and `ports/embeddings.py` (`EmbeddingPort`, `Embeddings` with `model` alias and `dim`). Composition is `adapters/registry.py::build_adapters`; provider SDK imports currently remain in adapters. No `ports/models.py` / `ModelCatalog` was found in this checkout.
- Current model identity/provenance: settings aliases `llm_model`, `embed_model`, ordered `embed_fallbacks`, and `embedding_dim`; local defaults in `core/settings.py`; pricing and the unused-by-production `LLM_CONFIG["fallbacks"]` in `config.py`; `MODEL_PRICING` and startup check in `api/main.py`/`workers/__main__.py`. Ingestion stores actual returned `Embeddings.model` plus dim on chunks (`adapters/pg_knowledge.py`, migration-backed columns); search filters by model+dim and health reports stale vector count. Exact/semantic cache keys include configured/actual embedding alias (`api/services/cache.py`, `adapters/redis_cache.py`) plus retrieval settings, but no digest/provider/region. No model digest lock/catalog or provider register exists in this checkout.
- Models need to be preflighted and allowed individually before every physical attempt; chosen immutable identity/route must be the one passed to the single-attempt adapter. Include synthesis retry, reasoning/verifier, query embedding, each ingestion batch, primary/fallback and any CrossEncoder/local inference if it remains a governed model. Current job submission preflight is insufficient for deferred workers. Decision-write failure already prevents governed work under existing gateway contract; extend that property to every attempt.

- **Gateway edition/basic views:** the same Decisions and receipt pages are core Gateway evidence views, not optional Assurance-only UI. `ui/src/features/overview/overview-page.tsx` and `ui/src/features/requests/request-drawer.tsx` also render decision summaries/traces; locate and update if API contract makes model identity available in those basic decision summaries. No separate provider page is in Sprint 013 nav placement; `ui/src/features/system/system-page.tsx` shows settings/health but should not become a substitute for decision evidence.
- Frontend API endpoint/type seams: `ui/src/api/endpoints.ts`, `ui/src/api/types.ts`, generated `ui/src/api/schema.d.ts`; UI contract driven by OpenAPI. Scope stated in Sprint 013 requirements: receipt JSON and Evidence > Decisions show provider, region and digest.

## Unknowns / architect decisions to settle before implementation

1. Accepted Sprint 012 snapshot may change imports, contracts, receipt canonicalization and UI summary shapes. Re-map against it; this preparation makes no assumption about final v2 schema.
2. Exact physical unit/attempt semantics and retry ownership across LiteLLM, ChatLiteLLM, provider SDKs and Ollama must be verified against the accepted lock, including retry knobs and request counts.
3. Whether CrossEncoder stays in scope as a governed catalog target or is disabled/replaced must be settled; it cannot remain an unrecorded physical inference path.
4. Ollama immutable digest invocation is runtime-specific; accepted image must be tested for completion, chat and embeddings. If it cannot bind a digest directly, readiness identifies verified read-only blobs plus closed mutation API as the safe boundary.
5. Provider register facts, possible processing destinations, storage geography, secret-reference format/resolver, price references (especially hosted embeddings), v1/v2 extension grammar and any local-only verifier runtime need final architect/owner contract decisions. Unknown provider facts cannot be claimed as verified residency.
6. UI must read the final signed extension/version shape from OpenAPI and preserve existing Gateway-only evidence/receipt operation when optional M2 features are off.
