# Sprint 012: Blueprint
- **Contract:**
  - `GET /v1/system/modules`, scope `kb:read` (as `/v1/config`), action `kb.read`. Response `ModuleList {edition: str | null, deploy_shape: str, modules: [ModuleInfo {name, label, pillar, enabled, nav_group, always_on}]}`. `pillar` is one of `platform`, `gateway`, `data`, `agents`.
  - A route of a disabled module answers 404 `module_disabled` in the standard error body, after a recorded deny.
  - `DecisionDetail` and `Receipt.decision` gain `record_version` and `extensions`. OpenAPI snapshot refreshed.
- **Ports (`ports/evidence.py`, `ports/data_access.py`, `ports/lineage.py`), strict mypy:**
  - `DecisionSink.write(entry: DecisionEntry, events: EventBus | None) -> UUID`. `DecisionEntry` is a frozen dataclass of today's row fields plus `extensions: Mapping[str, JsonValue]`. A failure raises.
  - `EvidenceLookup.decision(tenant_id, decision_id) -> EvidenceRef`. No-op returns `EvidenceRef(linked=False)`.
  - `DataAccess.read(...)`, a skeleton with one method. No-op raises `ModuleDisabled`, which the gateway records as `module_disabled`. The port grows later: 021 adds the real adapter and `current_snapshot`, 024 `extract`, 025 the metric methods, 029 `metric_catalog`, 026 `submit_write`. The contract suite grows each time and runs on the real and no-op adapters.
  - `LineageEmitter.emit(event)`. No-op drops the event and counts it (`dropped_count`).
  - `Adapters` and `PORT_NAMES` gain `decisions`, `evidence`, `data`, `lineage`. `adapters/registry.py` picks real or no-op from `ENABLED_MODULES`. No-ops live in `adapters/noop_modules.py`.
- **Evidence core (`evidence/`):** `record.py`, `chain.py`, `receipts.py`, `sink.py` (`PgDecisionSink`, real `DecisionSink`), `lookup.py` (`PgEvidenceLookup`). `GatewayRuntime` holds a `DecisionSink`; `enforce()` calls it. A raise on an allow still gives 503 `decision_unrecorded`.
- **Module registry (`core/modules.py`):** one `ModuleSpec` per module: `gateway` (M1 with evidence core, always on), `evidence` (M2), `agents` (M3: `api/agent`, `api/mcp`, `sandbox_agent`, the agent-run job handler), `data` (M4), `lineage` (M5). Sprint 029 adds `insights` (M6) and its nav group, and widens the Data edition to `gateway,data,lineage,insights`. Routers, job handlers and nav group are dotted-path strings, loaded by `api/main.py` and `workers/`, so `core` imports no module.
- **Settings:** `DEPLOY_SHAPE` (`single_tenant` default, or `multi_tenant`). In `single_tenant`, `scripts/admin/identity.py create-tenant` refuses a second tenant with a clear message, and startup logs the shape. RLS, `tenant_connection` and every tenant check are unchanged in both shapes. `ENABLED_MODULES`, comma list or `all` (default `all`, so behaviour is unchanged). Unknown names fail at startup. `gateway` is always on.
- **Import-linter (`[tool.importlinter]` in `pyproject.toml`, pinned in the dev group):**
  - `ports` imports no platform package. `core` imports no module package.
  - `evidence` does not import `gateway`, `api` or `workers`. `gateway` does not import `evidence`, `api` or `workers`.
  - `api.agent`, `api.mcp`, `sandbox_agent` do not import `evidence`, nor `gateway` internals. They may import the `gateway` package API (`gateway/__init__.py`), because every edition includes M1 and strict rule 4 needs `enforce()`.
  - The composition roots (`api/main.py`, `adapters/registry.py`, `workers/__main__.py`) may import any module.
- **Data:** migration (next free after the previous head) adds to `gateway_decisions`: `record_version SMALLINT NOT NULL DEFAULT 1 CHECK (record_version IN (1, 2))` and `extensions JSONB NOT NULL DEFAULT '{}'`. Existing rows stay version 1. No new table. `gap_app` keeps INSERT and SELECT only.
- **Record v2 (`evidence/chain.py`):** version 1 hashes the 13 fields as today. Version 2 hashes the same fields plus `record_version: 2` and `extensions`, all through `canonical_json` (sorted keys, no spaces). Extension keys are registered in `evidence/extensions.py` with a JSON Schema each; an unknown key or a float value is refused (JSONB would change it); the map is at most 4 KiB. New rows are version 2 with `{}` until a sprint registers a key. `scripts/verify/receipt.py` handles both versions.
- **Gateway:** new stage `module` after `principal`: an action whose module is off is denied `module_disabled`. `REASONS` gains `module_disabled` (stage `module`, `policy_field` None). Action-to-module map: `agent.run` and agent or MCP `tool.call` to `agents`. Each later sprint registers its kinds here: `data.*`, `access.*` and `product.certify` to `data`; `lineage.read` to `lineage`; `dashboard.write` and `report.*` to `insights`; `document.review` to `agents`. An unmapped kind fails a unit test, so no kind skips the stage.
- **Events:** none new. The decision event payload is unchanged.
- **UI (`.claude/skills/governed-design/SKILL.md`):** `NAV` items carry a `module`. The shell reads `/v1/system/modules` once per session and hides groups and items of disabled modules. New page `/app/modules` under Platform: a read-only table. Nav groups follow `docs/design/IA.md`; routes and labels stay the same.
- **CI:**
  - New script `scripts/ci/edition_smoke.sh [EDITION]`. It runs `ENABLED_MODULES=<edition> poetry run pytest -m edition_smoke` for Gateway (`gateway`), Assurance (`gateway,evidence`), Agents (`gateway,agents`), Data (`gateway,data,lineage`) and Full (`all`). With no argument it runs all five and exits non-zero if any fails. Each run boots the app with the real lifespan and fakes. Every later sprint runs this script.
  - `.github/workflows/editions.yml`, a matrix over the five editions. Each job calls `scripts/ci/edition_smoke.sh <edition>`.
  - `poetry run lint-imports` runs in the lint job.
- **Tests:** contract suites `tests/contracts/test_decision_sink_contract.py`, `test_evidence_lookup_contract.py`, `test_data_access_contract.py`, `test_lineage_emitter_contract.py`; `tests/unit/test_import_contracts.py` (tree passes; a temp tree with `evidence` importing `gateway.policy` fails); `tests/unit/test_settings_modules.py`; `tests/integration/test_module_disabled.py`; `tests/unit/test_action_module_map.py` (`test_every_action_kind_maps_to_module`); `tests/integration/test_record_v2.py`; `tests/integration/test_migration_record_v2.py` (upgrade from the previous head with chained rows); `tests/editions/test_edition_smoke.py`; `tests/unit/test_deploy_shape.py` (second tenant refused in `single_tenant`, allowed in `multi_tenant`, RLS policies present in both); `test_modules_have_pillars` (every `ModuleSpec` has a valid pillar); Vitest for nav filtering; Playwright `ui/e2e/modules.spec.ts`.
- **Showcase:** `scripts/showcase/README.md` names the journeys `m0`, `mg`, `md`, `ma`, `me` and the sprint that completes each (from `planning/program/sprint-map.md`). 014 writes the skeleton scripts.
- **Docs:** ADR-0013 (also the target gateway deployment modes: embedded, sidecar, standalone proxy; and the deploy shape), `docs/architecture.md` (modules, editions, ports), `docs/contracts/ports.md`, `docs/design/IA.md`, `planning/DOMAIN.md`, `docs/configuration.md` (generated).
