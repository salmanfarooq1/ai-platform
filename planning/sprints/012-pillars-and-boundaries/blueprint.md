# Sprint 012: Blueprint

Read `architect-disposition.md` for exact typed contracts and readiness decisions. Sprint 011 acceptance is the implementation prerequisite.
- **Contract:**
  - `GET /v1/system/modules`, scope union of every recognized existing credential scope (`require_any_scope(*Scope)`), action `system.read`, resource `system/modules`. This metadata-only action grants no KB/model/audit operation. Response `ModuleList {edition: str | null, deploy_shape: str, modules: [ModuleInfo {name, label, pillar, enabled, nav_group, always_on}]}`. `pillar` is one of `platform`, `gateway`, `data`, `agents`.
  - An authenticated, scoped call to a route of a disabled module answers 404 `module_disabled` in the standard error body, after a recorded deny. Existing 401/403 credential and scope behavior takes precedence.
  - `DecisionDetail` and `Receipt.decision` gain `record_version` and `extensions`. OpenAPI snapshot refreshed.
- **Ports (`ports/evidence.py`, `ports/data_access.py`, `ports/lineage.py`), strict mypy:**
  - `async DecisionSink.write(entry: DecisionEntry, events: EventBus | None = None) -> UUID`. Exact gateway-independent fields are in the disposition; the sink creates id/timestamp. A failure raises. No successful no-op sink exists.
  - `async EvidenceLookup.decision(tenant_id: UUID, decision_id: UUID) -> EvidenceRef`. Real lookup is always selected, even with M2 off. Unknown and foreign ids return identical unlinked values; the no-op is a contract fixture only.
  - `async DataAccess.read(*, tenant_id: UUID, resource: str) -> DataResult`, a typed skeleton with frozen result fields defined in the disposition. No-op raises `ModuleDisabled`, which the gateway records as `module_disabled`. The port grows later: 021 adds the real adapter and `current_snapshot`, 024 `extract`, 025 the metric methods, 029 `metric_catalog`, 026 `submit_write`. The contract suite grows each time and runs on the real and no-op adapters.
  - `async LineageEmitter.emit(event: CloudEvent, *, tx: Any = None) -> None`. No-op drops the event and counts it (`dropped_count`); this count is observability only. 022 adds a durable tenant-scoped spool before producers start, then 025 consumes it.
  - `Adapters` and `PORT_NAMES` gain `decisions`, `evidence`, `data`, `lineage`. `adapters/registry.py` always picks real decision/lookup adapters and selects the optional data/lineage adapters from `ENABLED_MODULES`. No-ops live in `adapters/noop_modules.py`.
- **Evidence core (`evidence/`):** `record.py`, `chain.py`, `receipts.py`, `extensions.py`. Thin `PgDecisionSink` and `PgEvidenceLookup` port adapters live in `adapters/pg_evidence.py`; the writer and canonical rules stay in the evidence package and import no gateway types. `GatewayRuntime` holds a `DecisionSink`; `enforce()` calls it. A raise on an allow still gives 503 `decision_unrecorded`.
- **Container packaging:** include the always-on `evidence/` package in the runtime Dockerfile's explicit COPY list. Build the final application image and prove Gateway-only startup/recording from that image, not only from the source checkout. Preserve the supply-chain build/scan path.
- **Module registry (`core/modules.py`):** one `ModuleSpec` per module: `gateway` (M1 with evidence core, always on), `evidence` (M2), `agents` (M3: `api/agent`, `api/mcp`, `sandbox_agent`, the agent-run job handler), `data` (M4), `lineage` (M5). Sprint 029 adds `insights` (M6) and its nav group, and widens the Data edition to `gateway,data,lineage,insights`. Routers, job handlers and nav groups are dotted-path strings, loaded only when enabled by the composition roots, so `core` imports no module. Agent job construction lives in `api.agent.jobs`; generic workers do not import/build graphs or sandbox runtimes. Existing ingest, KB/search, decisions, receipts and purge remain always on.
- **Settings:** `DEPLOY_SHAPE` (`single_tenant` default, or `multi_tenant`). In `single_tenant`, `scripts/admin/identity.py create-tenant` serializes count/create under a transaction advisory lock and refuses a second tenant with a clear message; startup refuses a multi-tenant database via a narrow SECURITY DEFINER boolean probe. PUBLIC execution is revoked; only `gap_app` gets EXECUTE. Startup logs the shape. The existing seeded tenant counts. Test fixtures needing two tenants explicitly use `multi_tenant`. RLS, `tenant_connection` and every tenant check are unchanged in both shapes. `ENABLED_MODULES`, comma list or `all` (default `all`, so behaviour is unchanged). Unknown names fail at startup. `gateway` is always on.
- **Import-linter (`[tool.importlinter]` in `pyproject.toml`, pinned in the dev group):**
  - `ports` imports no platform package. `core` imports no module package.
  - `evidence` does not import `gateway`, `api` or `workers`. `gateway` does not import `evidence`, `api` or `workers`.
  - `api.agent`, `api.mcp`, `sandbox_agent` do not import `evidence`, nor `gateway` internals. They may import the `gateway` package API (`gateway/__init__.py`), because every edition includes M1 and strict rule 4 needs `enforce()`. Only this internal-import constraint is direct-only (`allow_indirect_imports = true`): the permitted public facade itself imports its implementations. Keep the package-independence contracts transitive. Seed both `from gateway.policy import ...` and `from gateway import policy` to prove internal imports still fail.
  - The composition roots (`api/main.py`, `adapters/registry.py`, `workers/__main__.py`) may import any module.
- **Data:** migration (next free after the previous head) adds to `gateway_decisions`: `record_version SMALLINT NOT NULL DEFAULT 1 CHECK (record_version IN (1, 2))` and `extensions JSONB NOT NULL DEFAULT '{}'`, with CHECKs requiring an object and empty extensions on version 1. Online/offline verification rejects nonempty v1 extension claims rather than treating them as signed. Existing rows stay version 1. No new table. `gap_app` keeps INSERT and SELECT only. The migration also creates the narrow deploy-shape probe and filtered `jobs_claim(worker, lease, allowed_kinds TEXT[])`; revoke app/PUBLIC EXECUTE on the old unfiltered overload. NULL/empty kinds claim nothing. Filter expired-lease maintenance as well as normal claims; disabled jobs remain unchanged.
- **Record v2 (`evidence/chain.py`):** version 1 hashes exactly the 13 fields as today (see disposition; `trace_id` is not one of them). Version 2 hashes the same fields plus `record_version: 2` and `extensions`, all through `canonical_json` (sorted keys, no spaces). Extension keys are registered in `evidence/extensions.py` with a JSON Schema each; deep-copy/freeze extensions and reject an unknown key, floats/non-finite values or non-string object keys recursively before any write; canonical UTF-8 bytes are at most 4096. Returned API defaults never alter v1 hashing. New rows are version 2 with `{}` until a sprint registers a key. `scripts/verify/receipt.py` handles both versions.
- **Metadata authority:** add `ActionKind.SYSTEM_READ = "system.read"`, granted by each existing recognized scope and mapped to gateway. Unknown/empty scopes remain 403 and run-token path restrictions remain. A narrowed boundary may still remove the action. Test each single-scope key, including agent, audit, query and kb:write, and prove none gains additional data/model actions.
- **Gateway:** new stage `module` after `principal`: an action whose module is off is denied `module_disabled`. `REASONS` gains `module_disabled` (stage `module`, `policy_field` None). The module stage also checks trusted route-module attribution from the registry wrapper; preserve original scope/run-grant dependencies before this stage. This covers run reads, sandbox model calls and MCP opening whose actions otherwise map to gateway. Client-supplied module attribution is forbidden. Action-to-module map: `agent.run` and agent or MCP `tool.call` to `agents`. Each later sprint registers its kinds here: `data.*`, `access.*` and `product.certify` to `data`; `lineage.read` to `lineage`; `dashboard.write` and `report.*` to `insights`; `document.review` to `agents`. An unmapped kind fails a unit test, so no kind skips the stage.
- **Events:** none new. The decision event payload is unchanged.
- **UI (`.claude/skills/governed-design/SKILL.md`):** `NAV` items carry a `module`. The shell reads `/v1/system/modules` keyed to the signed-in identity, clears it on session change and hides optional groups until loaded. Both SideNav and CommandPalette consume that same filtered nav; no module-level unfiltered palette cache remains. It hides groups and items of disabled modules. New page `/app/modules` under Platform: a read-only table. Nav groups follow `docs/design/IA.md`; routes and labels stay the same.
- **Affected existing UI:** the inline Agent selector in `features/ask/ask-page.tsx` uses the same session-keyed module metadata as navigation. Unknown/off hides it and blocks a stale-mode submit; reset only the next manual choice and never auto-submit/reroute to Search. Search, Library, History, Requests/Decisions and basic Trust/receipt verification remain gateway foundation. Direct Agent runs URLs display module availability without polling disabled endpoints. Cover these states with Vitest and browser tests in this sprint, including Gateway edition with M2/M3 off.
- **CI:**
  - New script `scripts/ci/edition_smoke.sh [EDITION]`. It runs `ENABLED_MODULES=<edition> poetry run pytest -m edition_smoke` for Gateway (`gateway`), Assurance (`gateway,evidence`), Agents (`gateway,agents`), Data (`gateway,data,lineage`) and Full (`all`). With no argument it runs all five and exits non-zero if any fails. Each run boots the app with the real lifespan and fakes. Every later sprint runs this script.
  - `.github/workflows/editions.yml`, a matrix over the five editions. Each job calls `scripts/ci/edition_smoke.sh <edition>`.
  - `poetry run lint-imports` runs in the lint job.
