# Sprint 014: Architect readiness decisions

Read-only preparation by the dedicated Builder, reviewed by the Architect. Finalize the full pack against accepted 012/013 code before implementation. No fixture, database, key, model or branch was created by this audit.

- **One deployment tenant:** reuse an explicitly verified existing seed tenant. The default tenant from migration 0002 counts in single-tenant mode. Bind setup to tenant UUID and database identity; require a fresh/fixture-owned marker before adding personas or policy. Never silently create a second tenant, rename customer state or enable multi-tenancy.
- **Accurate personas:** the current policy is tenant-wide. Persona files specify credential scopes and refer to named journey policy scenarios; they do not create independent persona policies or claim later salary/masking enforcement. Use only currently implemented scopes.
- **Private idempotent credentials:** capture the CLI's one-time key output privately, with tracing off. Atomically write ignored `.showcase/keys.env` with mode 0600 in a private directory, rejecting symlinks/foreign ownership. Exclude private setup state from Docker/build contexts and evidence artifacts, not only git. Record only principal/key prefixes and desired scope hashes in a separate manifest. Reruns validate and reuse keys, creating no extra principals/keys. Replacement is explicit; missing/revoked/mismatched keys are never silently regenerated. Sentinel tests cover stdout, stderr, browser traces and artifacts.
- **External source only:** use a separate versioned forward-only migration tree under `data/reference-company/migrations/` and a revision/checksum ledger. The loader accepts a secret-referenced owner DSN, verifies expected database/fixture ownership, refuses the platform database, and touches only reviewed source tables. Extend the DDL gate narrowly for this migration tree and inspect its tooling; preserve existing violation tests. The read-only role has no write or DDL privilege. All published ports are loopback. No foreign truncation, volume deletion or destructive reset.
- **Bounded typed schema:** strict versioned table/column/key records with scalar types, classifications and enumerated generators. Reject unknown fields, SQL/default expressions, network references, invalid/incompatible keys, cycles and excessive sizes. Generate referenced keys first. Client-shaped output does not imply arbitrary client-schema database loading.
- **Byte determinism:** fix ordering, locale, encoding/newlines, decimals, data date origin and PDF metadata/ids. Use component-specific seeded randomness. Relative manifest entries contain media type, counts, byte length and SHA-256, with no current time, absolute path or self-hash. Refuse unowned output destinations. Faker may fill bounded seeded scalar values; names/domains/phones/bank/tax identifiers remain controlled fixture formats. Verify reserved domains/ranges, `TEST-` identifiers and deny-list scans; do not claim global proof that a fictional name has no real match.
- **Replayable changes:** `(dataset_id, seed, step)` identifies an operation and canonical before/after hashes. Apply its data mutation and journal atomically. Reruns verify recorded results without repeating mutations; key ordering preserves referential integrity. Prove deterministic independent sources and interruption rollback. No broker/replication setup in 014.
- **Correct M0 authority:** consumer performs denied search; auditor verifies receipt; agent developer proves the disabled-agent 404 after its scope check; any recognized scoped credential reads Modules through 012 system.read. Bind the denied model to 013 catalog identity and prove zero inference. Use an owned Gateway-only process, never restart another API. Fixtures establish an explicit baseline tenant policy; restore it by a new version on success/failure, only if the current head remains the journey's own version. Never delete history or overwrite a concurrent policy change. Cloud steps remain SKIP until 015.
- **Separate browser seed:** add a dedicated reference-company seed/project with 013 fake model catalog, preserving the existing default seed and assertions. Isolate policy-changing showcase servers from existing browser workers.

The final pack still needs concrete table/cardinality definitions beyond the required account/invoice/employee anchors, bounded PDF selection, generator subset, source migration runner and ownership-based fixture cleanup. These are fixture design choices, never asserted business rules. Capture small/medium repeat hashes, source role/replay checks, credential rerun/sentinel checks, local M0 receipt/module proof, dedicated browser journey and full inherited gates with unchanged API schema.
