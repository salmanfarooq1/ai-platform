# Sprint 016: Blueprint
- **Contract (`api/models/data.py`, router `api/routers/data.py`, module `data`):**
  - `GET /v1/data/datasets` (list for the nav page), `GET /v1/data/datasets/{id}/preview?limit=&snapshot=`, `GET /v1/data/datasets/{id}/snapshots`. Scope `data:read` (new in this sprint). `GET /v1/system/modules` keeps `kb:read`.
  - `{id}` is a table of the caller's catalog, `<schema>.<table>`, checked against the catalog's own table list (never put into SQL text unchecked). Sprint 017 maps registry ids onto it.
  - `DatasetPreview {dataset, snapshot_id, columns: [{name, type}], rows, truncated}`; `limit` 1 to `LAKE_PREVIEW_MAX_ROWS` (100).
  - Errors: 404 `dataset_not_found` (unknown or another tenant's, same body), 404 `snapshot_not_found`, 403 `dataset_not_allowed`, 504 `query_timeout`, 503 `lake_unavailable`. OpenAPI snapshot refreshed.
- **Port (`ports/query_engine.py`, strict):** `QueryEngine.list_tables(lake)`, `.current_snapshot(lake)` (DuckLake snapshots are catalog-wide, so one id per tenant catalog), `.snapshots(lake, table)`, `.preview(lake, table, limit, snapshot_id)`. `TenantLake` (tenant id, metadata schema, data path) and `TableRef` are frozen dataclasses. No raw SQL crosses the port.
- **Port `DataAccess` (013) gets its real adapter `dataplane/data_access.py`:** `read(...)` runs on a pinned snapshot through `QueryEngine`; new method `current_snapshot(principal) -> snapshot_id` returns the tenant catalog's current snapshot. One snapshot id per read, never a per-dataset map. The no-op adapter raises `ModuleDisabled` for both. Other modules reach lake data only through this port.
- **Adapter (`adapters/duckdb_engine.py`):** the only importer of `duckdb`.
  - One in-memory DuckDB instance per tenant, in an LRU cache of `DUCKDB_CONNECTION_CACHE_SIZE`. Each read takes a cursor from it.
  - Setup order: `LOAD ducklake, postgres, httpfs` from `DUCKDB_EXTENSION_DIR`; tenant-scoped S3 secret; `ATTACH 'ducklake:postgres:...' AS lake (METADATA_SCHEMA ..., DATA_PATH ..., READ_ONLY)`; then `allowed_directories` = the tenant data path, `enable_external_access=false`, `autoinstall_known_extensions=false`, `autoload_known_extensions=false`, `allow_unsigned_extensions=false` (start config), `memory_limit`, `threads`, and last `lock_configuration=true`.
  - Timeout: the read runs on a pool thread; after `DUCKDB_QUERY_TIMEOUT_SECONDS` the adapter calls `interrupt()`.
  - Reads use `AT (VERSION => snapshot_id)`.
- **Process model:** reads run in a bounded `ThreadPoolExecutor` (`DUCKDB_READ_THREADS`), never on the event loop. Job kind `data_query` runs heavy reads on a worker (`workers/handlers/data_query.py`); previews are always light.
- **Settings:** `LAKEHOUSE_DATABASE_URL` (catalog role, secret), `LAKE_S3_ENDPOINT`, `LAKE_S3_BUCKET`, `LAKE_S3_CREDENTIALS_FILE` (per-tenant read keys, file-mounted, never logged), `LAKE_DATA_ROOT` (local path when no S3), `DUCKDB_MEMORY_LIMIT` (1GB), `DUCKDB_THREADS`, `DUCKDB_READ_THREADS`, `DUCKDB_QUERY_TIMEOUT_SECONDS`, `DUCKDB_CONNECTION_CACHE_SIZE`, `DUCKDB_EXTENSION_DIR`, `LAKE_PREVIEW_MAX_ROWS`. Required only when the `data` module is on.
- **Data:** migration (next free number after the previous sprint's head) adds `lakehouse_catalogs (tenant_id PK FK, metadata_schema UNIQUE, data_prefix UNIQUE, s3_identity, created_at)`, RLS on `tenant_id`, `GRANT SELECT` to `gap_app`. DuckLake's own tables live in the `lakehouse` database: the written exception to strict rule 7 (ADR-0015). Role `gap_lake` owns the metadata schemas; it is neither superuser nor `BYPASSRLS`.
- **Provisioning:** `scripts/admin/lakehouse.py provision <tenant>` (owner role) creates the schema, the SeaweedFS identity limited to `s3://<bucket>/<prefix>/` (read only for the API), the row, and the credentials file entry.
- **Gateway:** new action kind `ActionKind.DATA_READ = "data.read"` (introduced here), resource `<schema>.<table>`. New scope `data:read`: added to the `Scope` enum in `core/identity/models.py` (so `scripts/admin/identity.py create-key --scopes` accepts it), to `SCOPE_ACTIONS` where it grants `data.read` only, and to `docs/api/README.md`. `kb:read` and `query` do not grant `data.read`. `tests/unit/test_auth.py` gains the new scope in its expected set. `PolicyDocument.allowed_datasets` (default `"*"` in `DEFAULT_POLICY`; left out of a tenant policy, it allows nothing) gives `dataset_not_allowed`. `REASONS` gains `dataset_not_allowed`, `query_timeout`, `lake_unavailable`. Action-to-module map (013): register `data.read` to `data`. `KNOWN_TOOLS`: no data tool exists until 027; record that in the report.
- **Snapshot pinning:** the route reads the current snapshot (or the requested one), calls `enforce()` with the record v2 extension `data` = `{table, snapshot_id}` (key registered in `evidence/extensions.py`; later sprints put their fields in their own extensions: `query`, `access`, `insight`, `on_behalf`), then reads at that snapshot.
- **Boundaries:** `dataplane/` (service code: lake lookup, snapshot pinning) imports only kernel, `ports` and the `gateway` package API. import-linter contracts and the `data` module spec gain it. `duckdb` joins `SDK_ONLY_IN_ADAPTERS` in `tests/import_lint.py`.
- **UI:** Data group (module `data`) with Datasets at `/app/data/datasets` (table list) and `/app/data/datasets/:id` (preview table with the snapshot id, and the snapshot list). Follows `.claude/skills/governed-design/SKILL.md`.
- **Compose and scripts:** `Dockerfile` installs the three extensions at build into `DUCKDB_EXTENSION_DIR`. `scripts/setup_db.sh` creates database `lakehouse` and role `gap_lake`. `scripts/verify/ducklake.sh` runs the read and isolation tests on SeaweedFS (`lake` profile).
- **Tests:** contract suite `tests/contracts/test_data_access_contract.py` grows to the real adapter (`test_read_pins_snapshot`, `test_current_snapshot_is_catalog_wide`) and keeps the no-op cases; contract suite `tests/contracts/test_query_engine_contract.py` (DuckDB on a throwaway `lakehouse` database and a temp data path); `tests/integration/test_lake_isolation.py` (each case below); `tests/integration/test_lake_lock.py`; `tests/integration/test_lake_snapshot_record.py`; `tests/integration/test_lake_event_loop.py` (heartbeat lag while a slow read runs, the pattern of `scripts/labs/lab_7.5_rerank_event_loop.py`); `tests/e2e/test_data_routes.py` (includes a key without `data:read` getting 403); Vitest for the pages; Playwright `ui/e2e/datasets.spec.ts`.
- **Personas:** `data/reference-company/personas/` (015): the consumer, producer and steward personas gain `data:read`.
- **Docs:** ADR-0015, `docs/api/README.md` (scope `data:read`), `docs/architecture.md` (data plane), `docs/operations.md` (provisioning, `ducklake.sh`), `docs/configuration.md` (generated), `docs/contracts/ports.md`.
