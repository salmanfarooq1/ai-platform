# Sprint 043: Blueprint
- **Contract** (`audit:read`; OpenAPI snapshot refreshed):
  - `GET /v1/evidence/compliance` gives `{frameworks: [{id, title, rows: [{ref, title, evidence: [{kind: test|doc, ref, status}], owner}]}], generated_at, source_commit}`. The data is the file built by the coverage check, read at start.
  - `GET /v1/evidence/systems/{id}/card` gives the system card JSON.
  - `POST /v1/evidence/systems/{id}/assessments` (`admin`): upload a completed assessment (`kind: iso42005|fria`, file up to `ASSESSMENT_MAX_BYTES`). Stored in the object store; its SHA-256 is recorded.
  - Packs (Sprint 042) gain `system-card.json`, `system-card.md`, `model-cards/`, `ml-bom.cdx.json`, `assessments/`, `compliance.json`, `redteam-summary.json` when present.
- **Data** (migration: next free number after Sprint 042's head; tenant_id + RLS + GRANT to `gap_app`):
  - `system_assessments`: `tenant_id, id, system_id` (references `ai_systems` from Sprint 042), `kind, object_key, sha256, uploaded_by, created_at`.
- **Files:**
  - `docs/compliance/mappings/{eu-ai-act,iso-42001-soa,nist-ai-rmf,nist-ai-600-1,sp-800-53,owasp-asi,owasp-llm-2026}.yaml`. A row: `ref`, `title`, `evidence[]` (pytest node id or doc path), `owner`, and for the SoA `applicable` plus `justification`.
  - `docs/compliance/model-cards/<model>.yaml`: intended use, limits, licence, source. The digest comes from `models.lock`, never typed by hand.
  - `docs/compliance/templates/iso-42005-impact-assessment.md` and `fria-art27.md`. A filled sample for the reference company system.
  - `docs/compliance/eu-ai-act-dates.yaml`: each obligation date with its CELEX source.
- **Generators** (`evidence/compliance/`): system card from the `ai_systems` row (Sprint 042), its principals (`ai_system_principals`), policies, models used, guard stages and eval runs, and a data-flow table with one row per outbound flow, including Insights `report.deliver` (in-app, PDF or CSV to recipients, Sprint 029); model cards; ML-BOM with CycloneDX `machine-learning-model` components, checked against the vendored CycloneDX 1.6 JSON schema.
- **Coverage check:** `scripts/compliance/check_mappings.py --junit <file> [--junit <file> ...]` (the unit run and the integration and e2e run). It fails when a row has no evidence or owner, a test id is not collected, a test did not pass in the given run, a doc path is missing, or any ASI01–ASI10 or LLM01–LLM10 item has no row. It writes `docs/compliance/coverage.json`.
- **Red team:** `scripts/redteam/release.sh` runs garak `0.17.0` and PyRIT `1.1.0` from a separate venv or container (`scripts/redteam/requirements.txt` with hashes, or a `redteam` image), outside the main Poetry lock, because they pull torch and hosted-model SDKs. garak has no licence field on PyPI; `licence-exceptions.txt` (011) (reviewed) names its real licence and the source checked. It runs garak and PyRIT against the local stack (fake or local model) and Strix against the local API. Strix may need a hosted model key; if it does, that part is a spend stop condition and is marked "not verified here". It writes `redteam-summary.json`: tool, pinned version, probe counts, findings per ASI and LLM item, hashes of raw reports. Raw prompts stay outside the pack. Manual or nightly, never in the default CI run.
- **Date check:** a unit test checks that every EU AI Act date in `docs/` matches `eu-ai-act-dates.yaml`. `scripts/compliance/check_eurlex.py` fetches the EUR-Lex text (manual, network) and compares. If the Omnibus is not adopted, the file says `pending` and docs say so. The same file lists the Art. 73 deadlines; a test compares them with the `INCIDENT_REPORT_DAYS` defaults (Sprint 039) and reports a difference as a question, never as a code change.
- **Gateway:** new action kind `evidence.assessment.upload`. No new stage.
- **UI** (follows `.claude/skills/governed-design/SKILL.md`): Evidence > Compliance. A framework switcher, a table of rows with status (passing test, document, gap), links to the test id or doc, the owner, and a system card view. Copy says "mapped to".
- **Tests:** generator unit tests (golden files); `test_system_card_has_insights_data_flow`; `test_redteam_tools_not_in_main_lock` (garak and PyRIT absent from `poetry.lock`); `test_redteam_pins` (garak `0.17.0`, PyRIT `1.1.0` in the red-team requirements); `test_licence_overrides_reviewed` (each override names a licence and a source); ML-BOM schema validation; model card digest equals `models.lock`; coverage check fails on a seeded missing test, a seeded failed test and a seeded unowned ASI item; assessment upload cross-tenant 404; date test; Playwright for the page.
- **Docs:** `docs/compliance/README.md` (how mappings work, what "mapped" means); `docs/operations.md` "Release red team"; `planning/DECISIONS.md` Q26 owners.
