# Sprint 017: Blueprint
- **Contract (`api/models/data.py`, `api/routers/data.py`):** OpenAPI snapshot refreshed.
  - **Contract change to 016 (breaking, stated on purpose):** from this sprint `{id}` is a registry dataset id (UUID), not the 016 `<schema>.<table>` form. The 016 routes `GET /v1/data/datasets/{id}/preview` and `GET /v1/data/datasets/{id}/snapshots` are removed and replaced by the per-table routes below. The UI is the only client and moves in this sprint. The OpenAPI diff, `CHANGELOG.md` and `docs/api/README.md` name the change. A test proves the old paths answer 404.
  - `GET /v1/data/datasets`, `GET /v1/data/datasets/{id}` (tables, current schema, schema versions). Scope `data:read` (016); action `data.read`.
  - `GET /v1/data/datasets/{id}/tables/{table}/preview?limit=&snapshot=` and `.../snapshots`, as in 016. `.../preview.csv`: the same rows as CSV, with formula neutralising (a cell starting with `=`, `+`, `-`, `@`, tab or carriage return gets a leading `'`).
  - `POST /v1/data/datasets` (`data:write`, action `data.write`): create a dataset.
  - `POST /v1/data/datasets/{id}/tables/{table}/uploads` (`data:write`, multipart, `Idempotency-Key`): stores the raw file by SHA-256 and answers 202 with a job. 413 `upload_too_large`, 415 `unsupported_format`.
  - `POST /v1/data/datasets/{id}/tables/{table}/erasures` (`admin`, body `{column, values}`): 202 with a job. `GET /v1/data/erasures/{id}`: status, rows deleted, unreplayable decision ids.
- **Data:** one migration (next free number after the previous sprint's head). All tables have `tenant_id`, RLS and grants to `gap_app`:
  - `datasets (id, tenant_id, slug, title, created_by, created_at)`, unique `(tenant_id, slug)`.
  - `dataset_tables (id, tenant_id, dataset_id, name, lake_table, created_at)`.
  - `dataset_schema_versions (id, tenant_id, table_id, version, columns JSONB, change TEXT CHECK (change IN ('initial','additive')), job_id, created_at)`.
  - `lake_retention (tenant_id PK, snapshot_retention_days, replay_window_days)`; no row means the settings defaults.
  - `lake_erasures (id, tenant_id, table_id, requested_by, values_sha256, rows_deleted, unreplayable_decisions UUID[], raw_files_deleted, status, created_at, finished_at)`.
  - An expression index on `gateway_decisions ((extensions->'data'->>'table'))` for the protected-snapshot lookup.
- **Jobs (`workers/handlers/`):** kinds `lake_upload`, `lake_maintenance`, `lake_erasure`. Only workers hold the writer S3 keys (`LAKE_S3_WRITER_CREDENTIALS_FILE`) and attach read-write. Locked connection as in 016, otherwise.
  - Writer lock: `pg_advisory_lock(hashtextextended('lake_writer:' || dataset_id, 0))` on a dedicated session for the whole write. A DuckLake conflict error retries up to `LAKE_WRITE_MAX_RETRIES` with backoff.
  - Upload: limits `LAKE_UPLOAD_MAX_BYTES`, `LAKE_UPLOAD_MAX_ROWS`, `LAKE_MAX_DECOMPRESSED_BYTES` (checked while streaming gzip, and from Parquet metadata before reading). Same columns: append. New nullable columns only: `ADD COLUMN` and a new schema version. Anything else: job fails with `schema_change_refused`. Idempotent by file SHA-256 and table.
  - Maintenance: per tenant and table, under the lock: `ducklake_flush_inlined_data`, `ducklake_merge_adjacent_files`, `ducklake_expire_snapshots` with an explicit version list (older than retention, minus protected), `ducklake_cleanup_old_files`. Protected = snapshot ids in `data.read` decisions inside the replay window.
  - Erasure: under the lock, delete matching rows, flush, expire every older snapshot that held them (protected ones too), clean up files at once, delete the raw upload objects that held the rows, and record the `data.read` decisions whose snapshot is gone.
- **Single write path (`dataplane/writer.py`):** every lake write (upload here; pipelines 018, dbt 019, CDC 020 later) goes through it. After a commit it emits the CloudEvent `platform.data.snapshot.committed.v1` with `tenant`, `dataset_id` and `snapshot_id`, through the outbox in the same transaction as the job result.
- **Scheduler:** `workers/scheduler.py` gains `schedule_lake_maintenance`, same pattern as `schedule_purges` (idempotency key with the UTC date, one job per tenant per day), in the same loop.
- **Settings:** `LAKE_UPLOAD_MAX_BYTES`, `LAKE_UPLOAD_MAX_ROWS`, `LAKE_MAX_DECOMPRESSED_BYTES`, `LAKE_WRITE_MAX_RETRIES`, `LAKE_SNAPSHOT_RETENTION_DAYS`, `LAKE_REPLAY_WINDOW_DAYS` (not above `DECISION_RETENTION_DAYS`), `LAKE_S3_WRITER_CREDENTIALS_FILE`, `LAKE_MAINTENANCE_INTERVAL_SECONDS`.
  - Placeholders: the upload limits, `LAKE_SNAPSHOT_RETENTION_DAYS` and `LAKE_REPLAY_WINDOW_DAYS` are business numbers. Each is a setting with a default, and the Builder logs a question for each in `planning/QUESTIONS.md`. They are not agreed rules.
- **Gateway:** new action kind `ActionKind.DATA_WRITE = "data.write"` (introduced here). New scope `data:write` (introduced here): added to the `Scope` enum in `core/identity/models.py` (so `scripts/admin/identity.py create-key --scopes` accepts it), to `SCOPE_ACTIONS` where it grants `data.write`, and to `docs/api/README.md`. `kb:write` does not grant `data.write`. `admin` for erasure. Resource is `<dataset slug>/<table>`. Action-to-module map (013): register `data.write` to `data`. Reasons: none new for the gateway; job errors use codes `schema_change_refused`, `write_conflict`, `upload_too_large`.
- **Events:** new `platform.data.snapshot.committed.v1` (`tenant`, `dataset_id`, `snapshot_id`), emitted only by the single write path. Insights alerts (029) consume it.
- **UI:** Data > Datasets list; dataset page with tabs Schema (versions), Snapshots, Preview. A snapshot picker sets "query as of" for the preview. CSV download of the preview.
- **Personas:** the producer persona (015) gains `data:write`.
- **Scripts:** `scripts/lake/seed_reference_company.py --size small` creates the finance, CRM and HR datasets and uploads through the API and jobs. `scripts/admin/lakehouse.py set-retention`.
- **Tests:** `tests/integration/test_lake_writer_lock.py` (two concurrent upload jobs on one table both succeed; a provoked conflict is retried); `test_lake_upload_limits.py` (size, rows, zip bomb, bad Parquet metadata); `test_lake_schema_versions.py`; `test_lake_maintenance.py` (protected snapshot survives expiry; unprotected one goes); `test_lake_erasure.py` (no readable row in any snapshot, in data files or in inlined catalog rows, raw object gone, decisions listed); `test_csv_export_neutralised.py`; `test_snapshot_committed_event.py` (`test_write_emits_snapshot_committed`: one event per commit with the new snapshot id, none on a failed write); `test_seed_load_reproducible.py` (two loads, same row counts and content hash per table); `tests/e2e/test_data_write_routes.py` (a key without `data:write` gets 403; the old 016 paths answer 404); Playwright `ui/e2e/datasets.spec.ts` extended.
- **Docs:** `docs/api/README.md` (scope `data:write`, the `{id}` change), `docs/operations.md` (writer lock, maintenance, erasure, backups runbook with the exact `pg_dump -Fc` and bucket copy commands and restore order), ADR-0015 (write path section), `docs/configuration.md` (generated).
