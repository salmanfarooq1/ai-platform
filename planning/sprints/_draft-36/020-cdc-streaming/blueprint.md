# Sprint 020: Blueprint
- **Contract:**
  - Dataset responses (Sprint 016–017 routes) gain `freshness`: `{source_committed_at, applied_at, age_seconds, source: "cdc" | "pipeline" | "upload"}`. OpenAPI snapshot refreshed.
  - `GET /v1/data/cdc/sources` (`data:read`): registrations with status (`active`, `paused`, `quarantined`), slot lag bytes, last applied offset per table. No connection detail, no secret, no connector config.
- **Ports and adapters:**
  - `ports/cdc.py`: `ChangeFeed` Protocol: `async poll(max_records, timeout) -> list[ChangeRecord]`, `async seek(positions)`, `async pause(topic)`. `ChangeRecord` is frozen: topic, partition, offset, key, value bytes.
  - `adapters/kafka_change_feed.py` reuses `KafkaConfig` and the aiokafka client from `adapters/kafka_event_bus.py`. Raw records, not CloudEvents (Debezium envelopes would be dead-lettered by `consume`).
  - Fake: `tests/fake_cdc.py` emits Debezium-shaped envelopes (`op`, `before`, `after`, `source.lsn`, `source.ts_ms`, schema) on top of the broker in `tests/fake_kafka.py`.
  - Settings, validated in `core/settings.py`: `CDC_BATCH_SECONDS` (10–30), `CDC_BATCH_MAX_RECORDS`, `CDC_GROUP_ID`, `CDC_TOPIC_RETENTION_HOURS`, `CDC_WAL_ALERT_BYTES`, `DATASET_FRESHNESS_WARN_SECONDS`, SASL user and password per client (`SecretStr`).
  - Placeholders: `CDC_TOPIC_RETENTION_HOURS`, `DATASET_FRESHNESS_WARN_SECONDS` and `CDC_WAL_ALERT_BYTES` are business numbers. Each is a setting with a default, and the Builder logs a question for each in `planning/QUESTIONS.md`.
  - Boundaries: `ports/cdc.py` (`ChangeFeed`) joins the import-linter contracts in `pyproject.toml`. `dataplane/cdc/` imports the port only, never `adapters/kafka_change_feed.py`. `aiokafka` stays an adapter-only SDK in `tests/import_lint.py`.
- **Sink** (`dataplane/cdc/sink.py`, run by `workers/cdc_sink.py`):
  - Topic → registration through a SECURITY DEFINER function `cdc_source_for_topic(topic)`. Unknown topic: record dropped and counted. Then all work runs under `tenant_connection` for that tenant.
  - Per table and batch: dedupe by primary key (last by LSN, then offset); drop rows with LSN ≤ the stored `last_lsn`; `c`, `u`, `r` become a `MERGE`; `d` deletes.
  - One DuckLake transaction per table and batch: data change, `_platform.cdc_offsets` (topic, partition, offset), `_platform.cdc_state` (table, last_lsn). On start the feed seeks to stored offsets + 1. Kafka commits are a convenience only.
  - The write goes through Sprint 017's write path: advisory lock on the dataset id, retry on conflict, and one `platform.data.snapshot.committed.v1` per committed batch and table.
  - Schema: a new nullable column becomes `ALTER TABLE ADD COLUMN`. A drop, rename, type change or a `source.db` that differs from the registration quarantines the batch, pauses that table's topic, and sets the table status to `quarantined`. Other tables continue.
  - Freshness: max `source.ts_ms` of the applied batch.
- **Decisions for open questions:** Q41: own process `cdc-sink`, so a slow sink never delays jobs. Q43: keep the explicit topic list; the sink builds its list from active registrations at start and on a registration change. Q44: accept the in-memory count for CloudEvent consumers; the CDC sink stores failures as quarantine rows, so its count does not matter. Q45: CDC topics get `retention.ms` from `CDC_TOPIC_RETENTION_HOURS` (placeholder default 168, must exceed the longest sink outage; question logged in `planning/QUESTIONS.md`); platform topics stay on broker default, noted in QUESTIONS.
- **Data** (migration: next free number after Sprint 019's head; `tenant_id`, RLS, GRANT to `gap_app`):
  - `cdc_sources`: id, tenant_id, name, connector_name, topic_prefix (`cdc.<id>`), source_db, tables JSONB (source table → dataset id), status, created_at.
  - `cdc_quarantine`: id, tenant_id, source_id, table_name, topic, partition, from_offset, to_offset, reason, payload_object_key, created_at. The raw batch goes to the object store, not the row.
  - `dataset_freshness`: tenant_id, dataset_id, source_committed_at, applied_at, source.
  - Function `cdc_source_for_topic`. Registration through `scripts/admin/cdc.py add-source` (owner role), not the API.
- **Source setup** (`data/reference-company/source/cdc.sql`, run by the profile's init job as the source owner): role `refco_cdc` with `LOGIN REPLICATION` and SELECT on listed tables only; `CREATE PUBLICATION refco_cdc_pub FOR TABLE ...`; heartbeat table. Debezium: `publication.autocreate.mode=disabled`, `slot.name=refco_cdc_slot`, `heartbeat.interval.ms=10000`, `snapshot.mode=initial`, JSON converter with schemas.
- **Kafka security:** listeners `SASL_PLAINTEXT` with `SCRAM-SHA-512` on the compose network; KRaft `StandardAuthorizer`; `allow.everyone.if.no.acl.found=false`. Users: `debezium` (write and create on prefix `cdc.`, Connect internal topics), `cdc-sink` (read prefix `cdc.`, group `cdc-sink`), `platform-relay` (write prefix `platform.`), `admin` (init job only). SCRAM users created at storage format.
- **Compose:** profile `cdc`: `kafka`, `kafka-init` (users, ACLs, topics), `debezium` (no `ports:`; `CONNECT_CONFIG_PROVIDERS=file`; secrets mounted read-only from `./secrets/`), `cdc-register` (one-shot, posts `docker/cdc/refco-connector.json` inside the network), `cdc-sink`. Postgres command adds `-c wal_level=logical -c max_replication_slots=4 -c max_wal_senders=4`. All images by digest.
- **WAL alert:** the sink samples `pg_replication_slots` on the source every minute into `cdc_replication_slot_retained_bytes`. Alert rule in `docker/observability/alerts.yml` at `CDC_WAL_ALERT_BYTES`.
- **CI:** a step sets `wal_level=logical` on the Postgres service (`ALTER SYSTEM`, then container restart) before the integration tier. Live CDC stays in `scripts/verify/cdc.sh` and a nightly job.
- **Events:** none new. CDC commits emit `platform.data.snapshot.committed.v1` through the 017 write path. Debezium records on CDC topics are raw records, not CloudEvents.
- **UI** (governed-design skill): `FreshnessBadge` on Data > Datasets rows and detail: age text, amber after `DATASET_FRESHNESS_WARN_SECONDS`, tooltip names the source.
- **Tests:** `tests/contracts/test_change_feed.py` (Kafka adapter in verify, fake in pytest); `tests/integration/test_cdc_sink_apply.py`; `test_cdc_sink_replay.py`; `test_cdc_sink_deletes.py`; `test_cdc_snapshot_committed.py` (`test_cdc_batch_emits_snapshot_committed`; a replayed batch emits none); `test_cdc_schema_changes.py`; `test_cdc_tenancy.py`; `test_cdc_secrets.py`; `test_cdc_source_setup.py`; `tests/unit/test_cdc_dedupe.py`; `tests/unit/test_compose_cdc.py` (parses the compose file); Playwright `ui/e2e/freshness.spec.ts`.
- **Docs:** ADR-0017, `docs/runbooks/cdc.md` (setup, slot cleanup, quarantine release), `docs/configuration.md`, `docs/deployment.md` (profile `cdc`), ADR-0008 note on the first consumer.
