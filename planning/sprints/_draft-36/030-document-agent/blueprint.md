# Sprint 030: Blueprint
- **Contract:**
  - `POST /v1/documents/{document_id}/extract` (scope `agent`; body `{contract_id, purpose}`) answers 202 with a job.
  - `GET /v1/documents/reviews?status=` and `GET /v1/documents/reviews/{id}` return fields, citations and status.
  - `POST /v1/documents/reviews/{id}/decision` takes `{action: approve|edit|reject, fields?}`. It needs `data:write` (from 017), because approve and edit publish to a dataset, and it goes through `enforce()`.
  - `GET /v1/documents/{document_id}/pages/{n}.png` returns a rendered page.
  - Unknown or foreign ids return 404 with the same body for both. Refresh the OpenAPI snapshot.
- **Parsing:**
  - Job kind `document_parse` runs Docling in a worker subprocess. Limits: 50 pages, 20 MB, 120 s, and an address-space limit.
  - It sets `DOCLING_ARTIFACTS_PATH=/models/docling`, `HF_HUB_OFFLINE=1`, `TRANSFORMERS_OFFLINE=1` and `DO_NOT_TRACK=1`.
  - The output (text blocks with `page_no` and `bbox`) is stored as a parse artifact in the object store under the tenant prefix.
- **Pre-fetch:**
  - An init job `docling-models` in the `models` profile downloads the layout, table and OCR weights once into the volume `docling-models`.
  - Each weight file's SHA-256, licence and source go into `models.lock`. The `models.lock` check from 014 covers them.
  - Weights are Apache-2.0 only. TableFormer (CDLA-Permissive-2.0 or Apache-2.0) is taken under Apache-2.0, recorded in `models.lock` and the ADR. If not, the parse runs with table structure off.
- **Extraction agent:**
  - Job kind `document_extract` starts an agent run on the `AgentRuntime` port (OpenShell, mandatory as in 027).
  - Tools: `read_document_page` (tag `reads_untrusted`, returns text blocks with block ids) and `describe_contract` (trusted).
  - The agent has no write tool. Its run result is a JSON object of fields, each citing block ids.
  - The worker, which is trusted code, validates the result against the JSON Schema derived from the ODCS contract. It maps block ids to page and box, then stores a review row.
- **Data** (migration: next free number after Sprint 029's head). Tables have `tenant_id`, FORCE RLS and a `GRANT` to `gap_app`:
  - `document_extractions (id, tenant_id, document_id, contract_id, contract_version, execution_id, fields jsonb, citations jsonb, status, created_by, reviewed_by, reviewed_at, publish_job_id)`.
  - `status` is one of `pending`, `approved`, `edited`, `rejected`, `published`.
  - A field without a citation is flagged `uncited`. It cannot be approved unedited.
- **Ports and adapters:** the `DataAccess` port gains `submit_write(principal, dataset_id, rows_ref) -> job_id`. The real adapter in `dataplane/data_access.py` queues the 017 write-path job. The no-op adapter raises `ModuleDisabled`. `tests/contracts/test_data_access_contract.py` grows for both adapters.
- **Publish:** approve or edit stores the rows as an object-store ref and calls `DataAccess.submit_write` for the contract's target dataset. The 017 job runs under the single-writer lock. The documents code does not import 017 write internals. The API never writes to the lakehouse.
- **Gateway:**
  - New action kind `document.review`. It registers with the `agents` module in the action-to-module map (013).
  - The taint from 027 applies. `read_document_page` sets it.
  - New reason code `extraction_invalid` for a result that fails the contract schema. It is recorded and the review row is not created.
- **Events:** `platform.documents.extraction.completed.v1` (no field values) on create and on each review decision.
- **UI:** Data > Documents.
  - The queue table, then a review view with the page image and SVG boxes per field.
  - Fields can be edited. Approve, edit or reject.
  - Extracted text renders as text only. Follow `.claude/skills/governed-design/SKILL.md`.
- **Reference set:** `data/reference-company/documents/` (from 015) with ground truth from the generators. `scripts/eval/documents/accuracy.py` scores field-level exact match per contract.
- **Malicious PDF:** `tests/fixtures/documents/malicious_invoice.pdf` is generated by a script. It holds white-on-white text and an off-page text block. They tell the agent to read HR salaries, call `send_report`, and add a markdown image link.
- **Tests:** `test_no_runtime_download` (network guard on, parse and extract succeed), `test_malicious_pdf_contained`, `test_citation_box_per_field`, `test_uncited_field_needs_edit`, `test_approved_rows_publish_via_write_path`, `test_review_rls`, `test_parse_limits`, `test_extraction_schema_enforced`, `test_publish_uses_data_access_port`, `test_submit_write_noop_module_disabled`, `test_document_review_maps_to_agents_module`, `test_docling_weights_licence_apache`, and the extraction contract test on the fake sandbox. Playwright: `documents-review.spec.ts`.
- **Compose and scripts:** the `docling-models` init job and volume. `scripts/verify/docling.sh` parses the reference set with the network off and prints the accuracy.
- **Docs:** `docs/architecture.md` (document path), `docs/operations.md` (model volume, limits), the API docs. ADR-0009 gets a short append for the extraction run and the Docling weights licence decision (Apache-2.0 only; TableFormer taken under Apache-2.0, else table structure off).
