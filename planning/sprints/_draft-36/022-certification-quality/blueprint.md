# Sprint 022: Blueprint
- **Contract** (under `/v1/data/quality`, governed; OpenAPI snapshot refreshed):
  - `GET /products/{id}`: current score, dimension scores, state, last evaluation, checks with result per snapshot.
  - `GET /products/{id}/evaluations`: history (score, state before and after, snapshot id).
  - `POST /products/{id}/evaluate` and `POST /products/{id}/profile` (`data:write`): 202 with the job.
  - `GET /products/{id}/drafts`; `POST /drafts/{id}/approve`, `POST /drafts/{id}/reject` (`data:steward`).
  - Certification stays on the Sprint 021 route: `POST /v1/data/products/{id}/transitions` with `to=certified`. A deny is 403 with the reason code.
- **Gateway:**
  - Action kind `product.certify` (from 021, granted only by `data:steward`). The 021 transition table maps `in_review → certified` to it. Draft approve and reject are `product.certify` actions too (`data:steward`, quality rule approval).
  - `Action` gains `context`: a frozen mapping of facts the server computed (never copied from a request body). It is hashed into the decision record, not stored in clear.
  - New stage `duties` in `gateway/stages.py`, after `policy` (introduced here; Sprint 023 extends it to `access.approve`). It acts only on `product.certify` in this sprint and reads server-built facts from `context`. Reasons, added to `gateway/reasons.py`: `separation_of_duties` (the principal moved the product to review, or owns it) and `certification_blocked` (for `in_review → certified`: a blocking check failed or was not run on the current snapshot). No other new stage.
  - The route builds `context` from `quality_evaluations` and `product_events`. The record v2 extension `data` (016) carries `snapshot_id` and gains `quality_evaluation_id` (schema updated in `evidence/extensions.py`). No new extension key.
- **Checks** (`dataplane/quality/`):
  - `autochecks.py`: `@auto_check(name, dimension, blocking)` registry. `missing_owner`, `missing_classification` (blocking); `pii_not_classified` (blocking; regex detectors for email, phone, IBAN, national id patterns on a sample, plus column-name hints); `no_lineage` (warning; returns `stub` until 025, which wires it to the `LineageLookup` port; it never reads lineage tables or `lineage/` code); `stale_data` and `broken_slo` (blocking when the contract sets an SLO).
  - `contract_rules.py`: compiles ODCS library rules (null values, duplicates, row count, valid values, ranges) to SQL from fixed templates (identifiers checked against the dataset schema and quoted, values bound as parameters), run on a pinned snapshot through `QueryEngine`. A rule of type `sql` is refused with `rule_type_not_supported`.
  - dbt-built products: the same rules become generated `schema.yml` tests and run with `dbt test` through the Sprint 019 runner.
  - Results hold counts and rates only, never row values.
- **Profiling** (`profile.py`): `SUMMARIZE` on the snapshot; `ydata-profiling==4.18.4` in minimal mode on `QUALITY_PROFILE_SAMPLE_ROWS` rows, with `YDATA_PROFILING_NO_ANALYTICS=True`. Drafts: not-null, unique, range, accepted values. An approved draft becomes a platform rule on the product (source `profile`, warning level). A steward can copy it into the next contract version; the 021 diff rules then apply.
- **Score and hysteresis** (`score.py`, pure functions): dimension rate = passed / evaluated; score = weighted sum with `QUALITY_WEIGHTS`. Degrade after `QUALITY_DEGRADE_AFTER` consecutive evaluations below `QUALITY_DEGRADE_BELOW` or with a blocking failure. Recover after `QUALITY_RECOVER_AFTER` consecutive evaluations at or above `QUALITY_RECOVER_AT` with no blocking failure. `QUALITY_RECOVER_AT` must be above `QUALITY_DEGRADE_BELOW` (validated). All defaults are placeholders: settings with a default, never agreed rules. Record each in `planning/QUESTIONS.md`. `QUALITY_PROFILE_SAMPLE_ROWS` and `QUALITY_EVAL_CRON` are placeholders in the same way.
- **Scheduling:** job kind `quality_evaluate` on the Sprint 018 scheduler, one schedule per certified or degraded product (`QUALITY_EVAL_CRON`). The evaluator moves `certified ↔ degraded` through the lifecycle table and writes a `product_events` row with actor `quality_evaluator` and the evaluation id.
- **Data** (migration: next free number after Sprint 021's head; `tenant_id`, RLS, GRANT to `gap_app`):
  - `quality_rules`: id, tenant_id, product_id, source (`contract`, `profile`, `auto`), rule JSONB, dimension, blocking, state (`draft`, `approved`, `rejected`), decided_by, decided_at.
  - `quality_evaluations`: id, tenant_id, product_id, snapshot_id, score, dimension_scores JSONB, blocking_failed, state_before, state_after, sha256, at. SELECT, INSERT only.
  - `quality_results`: id, tenant_id, evaluation_id, rule_id or check_name, snapshot_id, dimension, blocking, passed, measured JSONB (numbers). SELECT, INSERT only.
  - `quality_state`: tenant_id, product_id, consecutive_bad, consecutive_good.
- **UI** (governed-design skill; charts follow the dataviz rules): Data > Quality: score per product, dimension bars, checks table (blocking or warning, result, snapshot), score history with the state band, drafts queue with approve and reject.
- **Tests:** `tests/unit/test_autochecks.py` (`test_no_lineage_stub_until_lookup`); `tests/integration/test_certification.py::test_record_extension_data_fields`; `tests/unit/test_quality_score.py` (hysteresis table); `tests/unit/test_duties_stage.py`; `tests/integration/test_certification.py`; `test_contract_rules.py`; `test_dbt_contract_tests.py`; `test_profiling_drafts.py`; `test_quality_schedule.py`; `test_quality_tamper.py`; Playwright `ui/e2e/quality.spec.ts`.
- **Docs:** `docs/contracts/quality.md` (rule types, dimensions, score), reason codes in `docs/`, `docs/runbooks/quality.md`.
